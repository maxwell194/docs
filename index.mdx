## API capabilities

To ensure data integrity and security, the Infloww API currently operates under the following parameters:

- **Read-only access:** Pull data for analysis without the risk of altering or deleting data within your Infloww account.
- **Integration limits:** Only data retrieval is currently avaialble. Third-party tools requiring write or "action" permissions, such as external AI chatbots or automation platforms like Zapier, are not supported.

## **Request headers**

All API requests must include the following headers:

- **Authorization**: API key used for authentication. Provide the raw API key as the header value (do not include a "Bearer" prefix).
- **x-oid**: The agency identifier associated with your API key. ou can find this on the API key page in Infloww labeled as "Agency OID".

<Warning>
  If your request fails, please include the `x-request-id` from the response headers when contacting support. This helps our team quickly locate and diagnose the issue.
</Warning>

## **Rate limiting**

- **Agency limit**: A maximum of 1,000 QPM (queries per minmute) is enforced per agency, independent of the number of API key created.

## **Available endpoints**

- **Creator information:** General profile data for creators
  - Connected creators
  - All creators (including deleted)
- **Revenue breakdown:** Detailed earnings of each creator
  - Transaction details
  - Refund details
- **Transaction performance:** Sales attribution details with employee-level breakdowns. This supports all creators, including deleted or unlinked profiles.
- **Marketing analytics:** Statistics for promotions, free trial links, tracking links, and link fans
  - Tracking links
  - Free trial links
  - Profile promotions
  - Link fans
- **Employee data:** Employee lists and employee-to-creator assignments
  - Employee list
  - Employee's assigned creators
- **Employee reports:** Sales performance and chat activity breakdowns by employee
  - Sales statistics
  - Chatting statistics
- **Creator reports:** Daily performance metrics for creators
  - Platform ranking
  - Fan status (active and expired fans)
  - Subscriber growth (new and renewed fans)
  - Renewal status (fans with auto-renew turned on)
  - Subscription length
  - Chat activity (messages sent, fans chatted, PPVs)
  - Profile visitors
- **Message analytics:** Records of automated messages and priority mass messages
  - Automated messages
  - Priority mass messages

## **Data retention and availability**

The retention windows and data availability thresholds vary by endpoint, as detailed below:

| **Category** | **Endpoint** | **Retention Window** |
| :-- | :-- | :-- |
| Creator information | All endpoints | Full historical data |
| Revenue breakdown | All endpoints | Maximum of last 1 year of historical data |
| Transaction performance | All endpoints | Maximum of last 1 year of historical data |
| Marketing analytics | Tracking links | Full historical data |
| Marketing analytics | Free trial links | Full historical data |
| Marketing analytics | Profile promotions | Last 10,000 campaigns from up to 365 days ago, similar to availability on OnlyFans |
| Marketing analytics | Link fans | Full historical data |
| Employee data | All endpoints | Full historical data |
| Employee reports | All endpoints | Maximum of last 1 year of historical data |
| Creator reports | All endpoints | Maximum of last 1 year of historical data |
| Message analytics | All endpoints | Full historical data |

## **Data permissions**

API key permissions are configured upon creation and can be modified at any time.

- **Creator access:** You must explicitly select which creators the API key can access.
  - New or relinked creators are not automatically added to existing keys. You must manually edit the key's scope to include them.
  - Only the `/v1/transaction-perf/details` endpoint supports querying all creators (including deleted or unlinked). All other `creatorId`-based endpoints return connected creators only.
- **Employee access:** You must specify which employee data the API key can access. If you select **All employees**, the key's scope will dynamically update to include new staff members automatically, eliminating the need for manual adjustments.

## **Data synchronization and latency**

Data moves in two stages: from source platforms (such as OnlyFans) into Infloww, and then to the API. Total latency depends on platform sync schedules plus a one-hour buffer for the API to process updates from the app.

### **How data flows**

- **Stage 1 (Source platform to Infloww):** Infloww syncs data on a scheduled basis. General updates populate periodically, while heavier reporting data—such as employee and creator reports—can take up to 24 hours to reflect inside the app.
- **Stage 2 (Infloww to API):** Once data
