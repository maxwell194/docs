## **Access Requirements**

Only users with Owner or Admin roles can access API settings for security reasons.

## **Step 1: Generate your API key**

1. Log into your **Infloww account** and go to the API management portal.
2. Click **Create API key**.
3. Assign a descriptive **Name** to your new key.
4. Configure IP restrictions by adding trusted IP addresses (up to 5 recommended).
5. Set your API key **expiration period**—options range from 1 to 180 days. A 30-day expiration is recommended for security.
6. Choose the **API permissions**:
   1. Select which creators and employees the API key can access.
   2. Note that new creators are not added automatically; you must update the key’s scope manually.
   3. Choosing "All employees" dynamically updates the scope for new staff automatically.
7. Define **data point permissions** by selecting specific data fields the key can access, or choose "Select All".

<Tip>
  **Pro tip:** Use restricted IP access for better security. If your IP changes, access with the key will be blocked until a new key is generated.
</Tip>

## **Step 2: Secure your API key**

- Your full API key string is displayed **only once** during creation.
- Copy the API key immediately or download it for safekeeping.
- If you lose it, delete your old key and generate a new one.

## **Step 3: Manage your API keys**

- Edit your API key’s name, IP whitelist, and permissions anytime.
- Expiration cannot be changed after creation.
- You can have a maximum of **3 active API keys** per account.

## Data permissions

API key permissions are configured upon creation and can be modified at any time:

- **Creator access:** You must explicitly select which creators the API key can access. New or relinked creators are not automatically added to existing keys; you must manually edit the key's scope to include them.
- **Employee access:** You must specify which employee data the API key can access. If you select **All employees**, the key's scope will dynamically update to include new staff members automatically.
- **Unlinked / Deleted profiles:** Only the `/v1/transaction-perf/details` endpoint supports querying all creators (including deleted or unlinked). All other `creatorId`based endpoints return connected creators only.
